# Porting a Next.js storefront into WordPress

**Type:** client project, code private. **Skills shown:** React, Next.js internals, WordPress theme development, WebGL and canvas rendering, deployment automation, testing.

## Situation

A specialty e-commerce brand had a finished storefront design built as a Next.js 16 app on React 19, running on Cloudflare Workers with a D1 database. They wanted it inside WordPress, wired to WooCommerce for cart and checkout, with no headless setup.

## The constraint that shaped the work

The plan assumed `npm run build` would emit one JavaScript file and one stylesheet to enqueue from a PHP template. It does not. The app used React Server Components and a Worker runtime, and that architecture does not compile to a static bundle. Next.js is React, so the label was not wrong, but the whole plan rested on that one sentence and nobody had opened `package.json` before the work was assigned.

I raised it before writing code, and we agreed the port would be a genuine static React single-page app. Components and Tailwind carry over. Server components, the database layer and the Worker plumbing get replaced. The design stays untouched, which is what the client cared about.

## What I built

- A static React SPA that builds to `dist/index.js` and `dist/index.css`, enqueued from a WordPress child theme with a static front page.
- A deploy client with a verify step, followed by an anonymous, cookie-less fetch to confirm the site as a real visitor sees it.
- A 360 degree product label viewer, rewritten after the client reported visible seams in the first version. The label is generated SVG per product, baked into a texture and wrapped around a cylinder with a canvas projection. The hero and modal render through WebGL. The 38 product cards render through Canvas 2D, because browsers cap live WebGL contexts near 16.
- Label placement is generated by measuring the printed label on the product renders, not guessed in CSS. A `--check` mode fails loudly when the geometry file goes stale, so the label cannot silently drift off the bottle again.
- 27 unit tests covering the projection and texture logic.

## Result

The ported frontend has been live on the client's WordPress site since 2026-08-10, and the brand imagery was verified by anonymous fetch. The WordPress install, payment gateway configuration and email records sat with the client's technical side, outside my scope, so I built and tested up to that boundary.

## What I would point to

Reading the source before agreeing to the plan. The most valuable hour on this job was the one spent finding out that the plan's premise was wrong.
