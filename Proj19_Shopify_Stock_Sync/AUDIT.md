## Live run, Plan 4: rebuild decided from the published snapshot (2026-10-18)

The gap: n8n dispatched `refresh-catalog` only when its own tick changed Airtable. If the Airtable write landed and the dispatch after it failed, the retry tick found Airtable already matching Shopify, wrote nothing, and so never dispatched; the public page stayed behind for good. The fix (`code/plan_rebuild.js`) compares the stock Airtable holds after the tick with the committed snapshot the page is built from, and skips while a run is queued or running. Deployed into the live workflow (`YrF6YHaYAaUPyZBh`) by merging the new export with the live instance's own values (credentials, base id, sheet id). Each check was one real schedule tick: interval set to 1 minute, workflow activated, deactivated as soon as one execution finished. Test order `#1011` (1x `NYERI-PE-250g-WH`, Shopify 30 -> 29).
